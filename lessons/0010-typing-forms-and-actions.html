React 19 changed how forms get written. You'll see both styles in production — the classic onSubmit you already know, and the newer action prop. This lesson covers typing both, plus useActionState, the hook that pairs with them.

Recap: the classic way (still everywhere)

import type { SubmitEventHandler } from "react";   // FormEvent is deprecated

function CommentForm() {
  const [text, setText] = useState("");

  const handleSubmit: SubmitEventHandler<HTMLFormElement> = (e) => {
    e.preventDefault();
    api.post(text);            // text is controlled state — always current
  };

  return (
    <form onSubmit={handleSubmit}>
      <textarea value={text} onChange={(e) => setText(e.target.value)} />
      <button>Post</button>
    </form>
  );
}

Controlled inputs mean you have the value at all times — ideal when validation runs as the user types. But it's a lot of plumbing per field.

The React 19 way: the action prop

Pass an async function straight to the form. No preventDefault, no controlled state — inputs become uncontrolled, identified by their name:

async function addComment(formData: FormData) {
  const text = formData.get("text");     // ← FormDataEntryValue | null
  if (typeof text !== "string") return;  // narrow before use!
  await api.post(text);
}

function CommentForm() {
  return (
    <form action={addComment}>
      <textarea name="text" />
      <button>Post</button>
    </form>
  );
}

The typing contract:

  • Action type: (formData: FormData) => void | Promise<void> — React runs it in a transition and resets the form on success
  • The one gotcha: formData.get(name) returns FormDataEntryValue | null — that's string | File | null. It's never just a string. Always narrow (typeof x === "string") before using it. Forgetting this is the beginner bug with actions.
No name, no data. formData.get("email") reads the input's name attribute, not its id or label. Missing name = silent null.

useActionState — actions that report back

Most real forms need to show errors or results. useActionState wraps your action with a state slot:

import { useActionState } from "react";

interface FormState {
  error: string | null;
}

async function submitComment(prev: FormState, formData: FormData): Promise<FormState> {
  const text = formData.get("text");
  if (typeof text !== "string" || text.trim() === "") {
    return { error: "Comment can't be empty" };
  }
  await api.post(text);
  return { error: null };
}

function CommentForm() {
  const [state, submitAction, isPending] =
    useActionState(submitComment, { error: null });

  return (
    <form action={submitAction}>
      <textarea name="text" disabled={isPending} />
      {state.error && <p role="alert">{state.error}</p>}
      <button disabled={isPending}>{isPending ? "Posting…" : "Post"}</button>
    </form>
  );
}

Type inference does the work: state is FormState, inferred from the initial value { error: null }. The three returned values:

  1. state — whatever your action last returned (typed from the initial value)
  2. submitAction — the wrapped function, ready for <form action>
  3. isPending — boolean, true while the action's promise is running
The argument flip: inside useActionState, your action receives (prevState, formData) — previous state first. Without the hook it's just (formData). Mixing these up is the most common action bug.
Ties together everything so far: the error field is nullable state (Lesson 5 honesty), isPending drives UI (Lesson 3's rule — visible values need useState-style state), and for multi-field forms you'd graduate the error shape into a discriminated union (Lesson 2).

Recipe: typed forms & actions

  1. Simple submission → give inputs names, write async function x(formData: FormData), pass to <form action={x}>
  2. Every get() → narrow immediately: const v = fd.get("x"); if (typeof v !== "string") return;
  3. Need errors/results → define a FormState interface, wrap with useActionState(action, initialState); action signature becomes (prevState, formData)
  4. Return a fresh state object from every path of the action; render UI from it
  5. Use isPending for disabled/spinner states
  6. Live per-keystroke validation → fall back to controlled inputs + onSubmit with SubmitEventHandler<HTMLFormElement>
