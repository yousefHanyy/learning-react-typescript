Typing vi.fn() — when and why

Plain vi.fn() works. Add a generic only when you want the compiler to check arguments:

const onSave = vi.fn(); // works — but onSave(42) and onSave("oops") both compile
const onSaveTyped = vi.fn<(n: number) => void>(); // now onSaveTyped("oops") is a compile error

// same idea for spyOn — wraps an existing method:
const spy = vi.spyOn(api, "getJSON"); // typed from the real method — no generic needed
expect(spy).toHaveBeenCalledWith("/api/users");

Mocking context — wrap, don't mock the hook

When a component calls useAuth(), don't mock the hook — wrap with the real provider. You test the integration that ships:

function Wrapper({ children }: { children: React.ReactNode }) {
  return <AuthProvider>{children}</AuthProvider>;
}

render(<Profile />, { wrapper: Wrapper });
expect(screen.getByText(/welcome/i)).toBeInTheDocument();

// hook's own test — same wrapper trick:
import { renderHook } from "@testing-library/react";
const { result } = renderHook(() => useAuth(), { wrapper: Wrapper });

Mocking data — mock the boundary, not fetch

// don't mock global fetch — mock your wrapper (the ONE place as T lives):
vi.mock("../api", () => ({
  getJSON: vi.fn(async () => [{ id: "1", name: "Ada" }]),
}));

test("shows users", async () => {
  render(<UserList />);
  expect(await screen.findByText("Ada")).toBeInTheDocument();
});

Testing hooks & async forms

import { renderHook, act } from "@testing-library/react";

function useCounter(init = 0) {
  const [count, setCount] = React.useState(init);
  return { count, increment: () => setCount(c => c + 1) };
}

test("increments", () => {
  const { result } = renderHook(() => useCounter(10));
  expect(result.current.count).toBe(10);
  act(() => { result.current.increment(); }); // wrap state changes in act
  expect(result.current.count).toBe(11);
});
// async form — wait for the UI to settle:
test("shows zod error, then submits", async () => {
  const user = userEvent.setup();
  render(<LoginForm />);

  await user.click(screen.getByRole("button", { name: /sign in/i }));
  expect(await screen.findByText(/invalid email/i)).toBeInTheDocument();

  await user.type(screen.getByLabelText(/email/i), "ada@example.com");
  await user.type(screen.getByLabelText(/password/i), "hunter42!!");
  await user.click(screen.getByRole("button", { name: /sign in/i }));

  // findBy* waits async — getBy* would throw immediately before React flushed:
  await waitFor(() => expect(screen.queryByText(/invalid email/i)).not.toBeInTheDocument());
});

Use userEvent.setup() over fireEvent — full event sequence. Wrap async assertions in findBy* or waitFor.

Recipe: mocks, context & async

  1. Type a spy when you want checks: vi.fn<(data: Values) => void>(); otherwise vi.fn() is fine.
  2. Context: wrap with the real provider — render(<X />, { wrapper }) / renderHook(() => useX(), { wrapper }).
  3. Network: vi.mock("../api", () => ({ getJSON: vi.fn(async () => [...]) })) — mock the boundary, not fetch.
  4. Hooks: act(() => { result.current.increment() }).
  5. Async UI: await screen.findBy* or await waitFor(() => ...); use userEvent.setup() not fireEvent.
