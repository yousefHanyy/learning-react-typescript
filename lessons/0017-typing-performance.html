Why memo exists (and why juniors overuse it)

React re-renders a component when its parent re-renders — even if props didn't change. memo is a bail-out: "skip rendering if props are shallow-equal to last time."

As a junior you'll see it sprinkled everywhere. Most of it is wasted — or harmful. Memo has a cost (comparison + memory), and if props are new objects every render (which they are by default), it never bails out anyway. You pay to compare and still render.

Rule you can quote at work: don't memo until a measured problem exists. Profiler says this list is slow → memo the row. Not before.

Typing memo

memo needs no special generic — it infers from the component you pass:

import { memo } from "react";

interface RowProps {
  user: User;
  onSelect: (id: string) => void;
}

// Both equivalent — pick one style per codebase:
const Row = memo(function Row({ user, onSelect }: RowProps) {
  return <li onClick={() => onSelect(user.id)}>{user.name}</li>;
});

// or with explicit generic (rare — only when inference needs help):
const Row2 = memo<RowProps>(function Row2(props) { ... });

Types don't change. What changes is whether memo helps — that's about referential stability, which is where the next two hooks come in.

useMemo — memoizing a value

useMemo caches a value between renders. Its type is inferred from the factory's return:

// type inferred as User[] — no generic needed
const visibleUsers = useMemo(
  () => users.filter(u => u.role === filter),
  [users, filter]
);

// only annotate when the factory could return different shapes:
const result = useMemo<string | null>(() => {
  return found ? found.name : null;
}, [found]);
Gotcha: useMemo(() => ({ a: 1 }), []) gives you a stable { a: 1 } — but ({ a: 1 }) inline in JSX is a new object every render. If that object is a memo'd child's prop, the child re-renders despite being memoized. Stable values must come from useMemo (or useState).

useCallback — memoizing a function

useCallback caches a function identity. Same inference story — plus the dependency array is where juniors actually introduce bugs:

const handleSelect = useCallback((id: string) => {
  setSelectedId(id);
}, [setSelectedId]); // setSelectedId is stable (from useState) — safe dep

// typing the handler explicitly when needed (e.g. passing to a typed prop):
const handleChange = useCallback<React.ChangeEventHandler<HTMLInputElement>>(
  (e) => setValue(e.currentTarget.value),
  []
);

Why this matters for memo: a memo(Row) that receives onSelect={handleSelect} only skips when handleSelect is the same reference. Without useCallback, it's a new function every parent render → memo never bails out.

When it actually helps — the checklist

  1. Measured slowness. Profiler or visible jank, not "might be slow."
  2. Stable props. Use useMemo/useCallback for every object/function prop the memo'd child receives — otherwise the shallow compare fails.
  3. Child is expensive or many. Memo'ing a single cheap <div> saves nothing. Memo'ing 500 rows does.
// The only pattern worth memorizing:
const Row = memo(function Row({ user, onSelect }: RowProps) { ... });

function List({ users }: { users: User[] }) {
  const handleSelect = useCallback((id: string) => { ... }, []);
  // visibleUsers stable → Row's user prop stable per item
  const visibleUsers = useMemo(() => users.filter(...), [users]);

  return visibleUsers.map(u => (
    <Row key={u.id} user={u} onSelect={handleSelect} />
  ));
}

Skip all three until the checklist is met. Your reviewer will thank you.

Recipe: memo & friends

  1. Don't memo until the profiler says to. Most components are cheap.
  2. Wrap the child: const Row = memo(function Row(props: RowProps) { ... }) — types inferred.
  3. Stabilize object props with useMemo(() => ..., [deps]); type inferred.
  4. Stabilize function props with useCallback(fn, [deps]); type inferred, or useCallback<HandlerType>(fn, [deps]) when you need an explicit handler type.
  5. Verify: if any prop is still a new object/function each render, memo can't bail out — you just added cost.
  6. Prefer stable primitives and correct dep arrays over memo — memo is the last resort, not the first.
