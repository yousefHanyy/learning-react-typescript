Typing Props

~5 min · Glossary

Next: Events & State

The first thing you do for every React+TS component: type its props. Two patterns cover 90% of what you'll see in production.

interface (default)

interface ButtonProps {
  label: string;
  variant: 'primary' | 'secondary';
  disabled?: boolean;
  onClick: () => void;
}

function Button({ label, variant, disabled, onClick }: ButtonProps) {
  return <button className={`btn btn-${variant}`} disabled={disabled} onClick={onClick}>{label}</button>;
}
Convention: ComponentNameProps — e.g. ButtonProps, CardProps. This is what you'll see in every production codebase.

type (for unions/intersections)

type ButtonProps = {
  label: string;
  variant: 'primary' | 'secondary';
} & (
  | { onClick: () => void; href?: never }
  | { href: string; onClick?: never }
);
Rule: interface for plain objects. type when you need unions, intersections, or mapped types. Ask "could this be extended?" — if yes, use interface.

children

interface CardProps {
  title: string;
  children: React.ReactNode;
}

React.ReactNode accepts JSX, strings, numbers, null, undefined, and arrays — it's the standard choice.

Recipe: typing props

  1. interface ComponentNameProps { ... } — always this naming
  2. children → React.ReactNode
  3. Callbacks → arrow signatures: onClick: (id: string) => void
  4. Optional prop → disabled?: boolean
  5. Union of shapes or intersections → switch to type
