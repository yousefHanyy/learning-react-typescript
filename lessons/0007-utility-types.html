Utility Types

~7 min · Builds on: Lesson 1 (interfaces) · Lesson 4 (generics) · Glossary

← Lesson 5: Context & Custom Hooks Next: Exercise 2

Utility types are small, built-in type functions: you give them a type, they hand back a reshaped one. You don't write them — you use them. Five cover ~95% of what you'll reach for at work.

1. Pick & Omit — choose what to keep

Both start from an existing type and take or remove keys. The second argument must be a keyof the source — TS errors on typos.

interface User {
  id: string;
  name: string;
  email: string;
  password: string;
  createdAt: string;
}

// Only what a list row needs:
type UserPreview = Pick<User, "id" | "name">;
// = { id: string; name: string }

// Everything except the secret:
type PublicUser = Omit<User, "password">;
// = { id, name, email, createdAt }

// Real work example — extend native props but replace one:
interface SearchInputProps extends Omit<React.InputHTMLAttributes<HTMLInputElement>, "onChange"> {
  onChange: (value: string) => void;   // simpler signature
}
Pick vs Omit — how to decide: picking 2 of 10 fields? Use Pick. Removing 1 of 10? Use Omit. Both are fine — choose the shorter list.

2. Partial & Required — toggle optionality

// All props optional — perfect for "update" payloads:
type UserPatch = Partial<User>;
// = { id?: string; name?: string; email?: string; ... }

function updateUser(id: string, patch: Partial<User>) {
  // caller can pass { name: "New" } without the rest
}

// The opposite — force every prop to be present:
type CompleteConfig = Required<{ host?: string; port?: number }>;
// = { host: string; port: number }
Shallow only. Partial makes top-level keys optional — it doesn't recurse into nested objects. Partial<{ profile: { name: string } }> still requires profile.name if profile is provided.

3. Record — a typed dictionary

type Role = "admin" | "editor" | "viewer";

// Every Role must have an entry — TS enforces completeness:
const permissions: Record<Role, string[]> = {
  admin:  ["read", "write", "delete"],
  editor: ["read", "write"],
  viewer: ["read"],
  // missing "viewer"? ❌ error
};

// Free-form string keys:
const cache: Record<string, User> = {};
cache["42"] = { id: "42", name: "Ada", email: "...", password: "...", createdAt: "..." };

4. React's own helpers — wrapping a native element

The real-world job: you build a design-system <FancyButton> that looks custom but should accept every normal <button> prop (onClick, disabled, type, aria-*, …). Listing them by hand is endless and always incomplete:

// ❌ Manual — you will forget props, and you repeat React's work:
interface BadFancyButtonProps {
  label: string;
  onClick?: () => void;
  disabled?: boolean;
  // ... what about type? form? aria-label? className? — endless
}

React.ComponentProps<"button"> solves it: it's a utility that expands to "every prop a <button> accepts, already typed". One line, always complete:

type AllButtonProps = React.ComponentProps<"button">;
// = { onClick?: ..., disabled?: boolean; type?: "button" | "submit" | "reset"; children?: ReactNode; ... }

So wrapping becomes:

interface FancyButtonProps extends React.ComponentPropsWithoutRef<"button"> {
  label: string;   // your extra prop, plus everything a <button> has
}

function FancyButton({ label, className, ...rest }: FancyButtonProps) {
  return (
    <button className={`fancy ${className ?? ""}`} {...rest}>
      {label}
    </button>
  );
}

// Usage — all native props just work, fully typed:
<FancyButton label="Save" onClick={handleSave} disabled type="submit" />

Two variants exist — they differ only on ref:

  • ComponentProps<"button"> — includes ref
  • ComponentPropsWithoutRef<"button"> — same, but without ref. Use this when your wrapper doesn't forward a ref (most cases).

And when your wrapper replaces a prop, combine with Omit. This is the same trick from section 1's SearchInputProps — remove the original, add your version:

// FancyButton decides its own children from `label`, so forbid `children`:
interface StrictFancyButtonProps
  extends Omit<React.ComponentPropsWithoutRef<"button">, "children"> {
  label: string;
}

<StrictFancyButtonProps label="Save">Oops</StrictFancyButtonProps> // ❌ children is gone — use label instead
Shorthand. ComponentProps<"input"> is just a short alias for the longer React.InputHTMLAttributes<HTMLInputElement> you saw in section 1. Same result, less typing.

Recipe: utility types

  1. Subset by name → Pick<Source, "a" | "b"> (short keep-list) or Omit<Source, "x"> (short remove-list)
  2. All optional → Partial<T>; all required → Required<T> (shallow)
  3. String-key dictionary → Record<KeyType, ValueType>
  4. Wrapping a native element → React.ComponentProps<"tag"> + Omit to replace a prop
  5. Union surgery → Exclude<Union, "a"> / Extract<Union, "a">
