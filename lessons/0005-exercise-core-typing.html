Challenge 1 · Lesson 1

Type a Badge component

Objective: write an interface and annotate a component.

Define BadgeProps for a badge that has:
  • label: string (required)
  • color: one of 'green' | 'red' | 'blue' (required)
  • onClick: optional — a function taking no args, returning nothing
  • children: anything renderable (required)
Then write the component signature: function Badge(props: BadgeProps) { ... } using destructuring.

Solution

interface BadgeProps {
  label: string;
  color: 'green' | 'red' | 'blue';
  onClick?: () => void;
  children: React.ReactNode;
}

function Badge({ label, color, onClick, children }: BadgeProps) {
  return (
    <button className={`badge badge-${color}`} onClick={onClick}>
      {label}
      {children}
    </button>
  );
}
Challenge 2 · Lesson 2

Fix the state bug

Objective: spot and fix a useState typing error.

This code fails to compile. Find the error and fix it, then type the submit handler correctly:

interface Comment { id: number; text: string; }

function Comments() {
  const [comments, setComments] = useState([]);           // ❌
  const handleSubmit = (e) => {                           // ❌
    e.preventDefault();
    setComments([...comments, { id: 1, text: 'hi' }]);
  };
  return (
    <form onSubmit={handleSubmit}>
      <input type="text" />
      <button type="submit">Add</button>
    </form>
  );
}

Solution

function Comments() {
  const [comments, setComments] = useState<Comment[]>([]);   // ✅ typed array

  const handleSubmit: React.SubmitEventHandler<HTMLFormElement> = (e) => {
    e.preventDefault();
    setComments([...comments, { id: 1, text: 'hi' }]);
  };
  // ...
}
Challenge 3 · Lesson 3

Autofocus a video ref

Objective: type a DOM ref correctly.

Write a component that mounts a <video> element and calls play() on it when mounted. Use useRef, useEffect, and a type guard so TypeScript is happy. Then expose the ref to parents as a ref prop (React 19 style).

Solution

function VideoPlayer() {
  const videoRef = useRef<HTMLVideoElement>(null);

  useEffect(() => {
    videoRef.current?.play();   // ✅ optional chain handles the null
  }, []);

  return <video ref={videoRef} />;
}

// Exposing to a parent (React 19 — ref is a prop):
interface VideoProps {
  src: string;
  ref?: React.Ref<HTMLVideoElement>;
}

function Video({ src, ref }: VideoProps) {
  return <video src={src} ref={ref} />;
}
Challenge 4 · Lesson 4

Make a generic KeyValueTable

Objective: write your own generic component.

Build a generic KeyValueTable<T> that renders a table from items. Props:
  • items: T[]
  • columns: { key: keyof T; header: string }[]
Render one row per item, one cell per column, showing item[column.key]. Then constrain T so keyof T is safe. It should work for any object type without any.

Solution

interface Column<T> { key: keyof T; header: string; }

interface KeyValueTableProps<T> {
  items: T[];
  columns: Column<T>[];
}

function KeyValueTable<T>({ items, columns }: KeyValueTableProps<T>) {
  return (
    <table>
      <thead>
        <tr>{columns.map((c) => <th key={c.header}>{c.header}</th>)}</tr>
      </thead>
      <tbody>
        {items.map((item, i) => (
          <tr key={i}>
            {columns.map((c) => (
              <td key={c.header}>{String(item[c.key])}</td>
            ))}
          </tr>
        ))}
      </tbody>
    </table>
  );
}

// Usage — T is inferred as User:
const users: User[] = [/* ... */];
<KeyValueTable items={users} columns={[{ key: 'name', header: 'Name' }]} />;
Stretch · Lesson 4

Add a render prop to KeyValueTable

Objective: make cells customizable with an optional renderer.

Modify Challenge 4 so a column can optionally render a custom React node when the value isn't a plain string — e.g. dates, badges, links:
  • Add render?: (value: T[keyof T]) => React.ReactNode to Column<T>
  • When render is present, use it; otherwise fall back to String(value)

Solution

interface Column<T> {
  key: keyof T;
  header: string;
  render?: (value: T[keyof T]) => React.ReactNode;
}

interface KeyValueTableProps<T> {
  items: T[];
  columns: Column<T>[];
}

function KeyValueTable<T>({ items, columns }: KeyValueTableProps<T>) {
  return (
    <table>
      <thead>
        <tr>{columns.map((c) => <th key={c.header}>{c.header}</th>)}</tr>
      </thead>
      <tbody>
        {items.map((item, i) => (
          <tr key={i}>
            {columns.map((c) => {
              const value = item[c.key];
              return (
                <td key={c.header}>
                  {c.render ? c.render(value) : String(value)}
                </td>
              );
            })}
          </tr>
        ))}
      </tbody>
    </table>
  );
}

// Usage:
<KeyValueTable
  items={users}
  columns={[
    { key: 'name', header: 'Name' },
    { key: 'createdAt', header: 'Joined', render: (d) => new Date(d).toLocaleDateString() },
  ]}
/>

Two things worth noticing:

  1. T[keyof T] is index access on the type level — "whatever type the pointed-at property has". It can't be written precisely without the generic, which is why this pattern only works on generic components.
  2. The optional-call guard: c.render ? ... : ... isn't just runtime safety — it's what lets TS accept calling c.render(value), since within that branch render is definitely defined. This is exactly the narrowing you saw with discriminated unions in Lesson 2.

This is the same pattern React's own docs use for list components (renderItem) — see the glossary's Patterns section.
