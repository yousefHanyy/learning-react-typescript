Lesson 3

Typing Refs

~6 min · Builds on: Lesson 1, Lesson 2 · Glossary

← Lesson 2: Events & State Next: Generic Components

Refs come in two flavors at work, and TS types them differently. This lesson covers both, plus the current way to expose a ref from a custom component.

1. DOM refs: useRef<T>(null)

function SearchBox() {
  const inputRef = useRef<HTMLInputElement>(null);

  useEffect(() => {
    inputRef.current?.focus();   // ✅ optional chaining
  }, []);

  return <input ref={inputRef} />;
}

Because the initial value is null, TS types current as HTMLInputElement | null. You must check before using — hence ?.focus() or an if guard.

Never do this: useRef<HTMLInputElement>() with no argument. It returns undefined initially, but the type lies and says HTMLInputElement — you get a non-null reference to nothing. Always pass null for DOM refs.

2. Value refs: useRef<number>(0)

function Timer() {
  const intervalRef = useRef<number | null>(null);

  function start() {
    intervalRef.current = window.setInterval(tick, 1000);
  }

  function stop() {
    if (intervalRef.current !== null) {
      clearInterval(intervalRef.current);
      intervalRef.current = null;
    }
  }
}

useRef is right here because mutating current does not trigger re-renders — you need the id to persist across renders, but the UI never changes when it does. Initialized with a real value, so current is plain number | null.

Don't use useRef for a visible counter. Ref mutations never re-render, so the UI would stay frozen. If a value must appear on screen, that's useState. Refs are for values that persist silently: timer ids, previous-prop trackers, flags, scroll positions.

The generic <number> is the same mechanism you asked about with useState<RequestState>.

3. Passing refs to components (React 19)

Since React 19, ref is just a normal prop. Type it with React.Ref<T> — which accepts both object refs and callback refs:

interface InputProps {
  label: string;
  ref?: React.Ref<HTMLInputElement>;   // typed like any prop
}

function LabeledInput({ label, ref }: InputProps) {
  return (
    <label>
      {label}
      <input ref={ref} />
    </label>
  );
}
React 18 codebases (still common): you'll see forwardRef instead — forwardRef<HTMLInputElement, InputProps>((props, ref) => ...). The type arguments are always <RefType, PropsType>. Just recognize it; new code uses the prop form above.

Recipe: refs

  1. DOM element → useRef<HTMLInputElement>(null), attach with ref={...}, always guard: .current?.focus()
  2. Silent persisted value → useRef<number | null>(null), mutate .current freely — no re-render
  3. If it shows on screen → that's useState, not a ref
  4. Forwarding to your own component → ref?: React.Ref<T> as a normal prop (React 19)
